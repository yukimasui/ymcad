# Phase 0 — IME 検証スパイク

`egui` の `TextEdit` 上で Ubuntu の日本語入力 (ibus / mozc) が成立するかを、**人間が目視で判定する**ための最小アプリ。

ymcad 本体のワークスペースからは意図的に分離してある（`spikes/` 配下の独立クレート）。Phase 0 の結論が出て `docs/DECISIONS.md` に記録されたら削除してよい。

## 起動

```bash
# Wayland ネイティブ（本命）
cd spikes/ime-check
cargo run

# X11 / XWayland で比較したい場合
#   ※ WINIT_UNIX_BACKEND は winit 0.30 で廃止済み。
#     winit は WAYLAND_DISPLAY が空なら DISPLAY を見て X11 を選ぶ。
WAYLAND_DISPLAY= cargo run

# winit が受け取っている生の IME イベントも見たい場合
RUST_LOG=egui_winit=debug,winit=debug cargo run
```

## 判定してほしいこと

入力欄をクリックし、半角/全角キー（または Super+Space）で IME を ON にして `nihongo` と打ち、Space で変換、Enter で確定してください。
中央の入力欄①と下部の入力欄②の両方で試してください（②は ymcad 本体のコマンドラインと同じ位置です）。

| # | 確認項目 | PASS の見え方 |
|---|---|---|
| 1 | 変換候補ウィンドウが表示されるか | 入力中に mozc の候補ポップアップが画面のどこかに出る |
| 2 | 候補ウィンドウがカーソル位置に追従するか | 入力欄①と②で候補ウィンドウの出る位置が変わる（後述の注意を参照） |
| 3 | 未確定文字列がインライン表示されるか | `にほんご` が**入力欄の中に下線付きで**出る。同時に「確定済みバッファ」表示にも未確定文字列が入る |
| 4 | 確定文字列が正しくバッファに入るか | 確定後、`日本語` が入力欄とバッファ表示に正しく入る（文字化け・重複・欠落なし） |
| 5 | IME 有効化 API の明示呼び出しが必要か | 入力欄をクリックすると画面の【項目5】行が緑（`set_ime_allowed(true)`）に変わる |

### 判定時の注意

- **`Enabled` / `Disabled` イベントは飛んできません。** egui 0.36 でこの 2 つは `#[deprecated]` になり、egui-winit が winit の該当イベントを捨てています。ログに出ないのが**正常**です。期待するログは `Preedit` が数回 → `Commit` です。
- **項目 2 について**: egui 0.36 は候補ウィンドウの位置に `IMEOutput::rect`（TextEdit ウィジェット**全体**の矩形）を使い、`cursor_rect`（キャレット位置）は計算はするものの使っていません。つまり候補ウィンドウは「キャレット直下」ではなく「**入力欄の左端**」に出るのが仕様どおりの挙動です。「入力欄①と②で位置が変わる」なら追従は機能していると判定してください。
- **日本語が □（豆腐）になる場合**: 画面上部の「環境情報 / フォント」を開いてフォント読み込み状況を確認してください。`sudo apt install fonts-noto-cjk` で解決します。これは IME の問題ではありません。
- 項目 5 は、このアプリが `set_ime_allowed` / `set_ime_cursor_area` を**自前で一切呼んでいない**ことが根拠です。それでも動くなら「明示呼び出しは不要」と結論できます。
